# Cycluna — native rebuild (this repo: `cycluna-app`, PUBLIC)

## What Cycluna is
A menstrual-cycle + moon-phase tracker: cycle/phase prediction, moon phases, an
**end-to-end-encrypted journal**, mood & headache logs, shareable cycle snapshots,
and reminders. It is being **rebuilt as native iOS (SwiftUI) + Android (Jetpack
Compose)** on top of a **Kotlin Multiplatform (KMP) shared core**, backed by a
**self-owned Cloudflare backend** — migrating OFF the original Lovable + Supabase
web app.

## The three repos (siblings under `WorkoutTimer/`)
- **`cycluna-app`** (this repo, **PUBLIC**): KMP shared core + native apps. **No secrets** — only the public Cloudflare Worker URL.
- **`cycluna-backend`** (**PRIVATE**): Cloudflare Workers + D1 schema + migration tooling. Not built yet. Full plan: `../cycluna-backend/docs/native-migration-plan.md`.
- **`cycluna-moon-flow`** (**ARCHIVE — do not modify**): the original Lovable/Vite/React + Supabase web app. **Behavioral reference only** — we port logic *from* here.

## The web app is the behavioral reference
When porting, the source of truth is `../cycluna-moon-flow/src/lib/*`. Match behavior
exactly wherever it touches persisted data. Key files:

| Web reference | Native target | Status |
|---|---|---|
| `moon.ts` | `shared` `Moon.kt` | ✅ ported |
| `cycle.ts` | `shared` `Cycle.kt` | ✅ ported |
| `phaseContent.ts` | phase copy (native layer, not core) | ⏳ |
| `crypto.ts` / `letterCrypto.ts` | journal `enc:v1` AES-GCM via `expect/actual` | ⏳ |
| `passkey.ts` (WebAuthn) | native passkey APIs (ASAuthorization / Credential Manager) | ⏳ |
| `push.ts` (web-push/VAPID) | **replaced** by APNs (iOS) + FCM (Android) | ⏳ |

⚠️ **JS `Math.round` is half-up**; Kotlin's `roundToInt` is half-to-even. `Moon.kt`
uses `floor(x + 0.5)` to match the web app exactly — preserve this in any numeric port.
(`Cycle`'s gap averaging, which also needed it, was removed with cycle-length learning.)

### Deliberate divergences from the web app — do NOT "restore parity"
The fidelity rule above is scoped to behavior **touching persisted data**. These are
derived values, and the web behavior is wrong for a native app that models lateness:

| Rule | Web (`cycle.ts`) | Cycluna | Why |
|---|---|---|---|
| Relearn cycle length | from **1** gap | **never** — the configured setting is the contract | Learning absorbed lateness (one long gap became the new baseline, so the next late period looked normal) and silently overrode a number the user chose. History is recorded exactly as logged; predictions always use the setting. |
| `status()` anchor | rolls forward by whole cycles | never rolls | Rolling reported "Day 1 · Menstrual" on a day no period arrived, and made lateness impossible to express. |
| `nextPeriodIso` | rolls the anchor first | anchor + one cycle | Rolling skipped an overdue period and pointed a whole cycle ahead. |

## Architecture rules
- **`shared/` = pure domain logic only.** No UI, no platform APIs. Swift/Android call it.
- **Keep the core LEAN.** Domain models only — UI copy/colors live in the *native* layer,
  NOT the core. (We deliberately dropped `colorVar`/`hormoneHighlight` from `Phase`.)
- **Platform-native** (per platform): all UI, charts, passkeys, secure key storage
  (Keychain / Keystore), push, on-device reminders. Use **`expect/actual`** for crypto
  and secure storage so the format/logic is written once, implemented natively.
- **UI-first**: build screens, let the data model *emerge*, then design the D1 schema.
  Do **not** faithfully port the old Supabase schema — there are **0 users**, so no data
  migration; the old schema is a checklist of concepts only.

## Stack / toolchain (verified working)
- **Kotlin 2.2.0**, Gradle wrapper **8.11.1**, `kotlinx-datetime` 0.6.1
- Build/test JVM: **Temurin JDK 17** — NOT the Homebrew JDK 26 (too new for this Gradle).
  Always set: `JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home`
- **Compile toolchain is JDK 21** (`jvmToolchain(21)` in `shared` and `androidApp`):
  F-Droid's build image ships only JDK 21, and reproducible builds need our APK built
  with the same toolchain F-Droid rebuilds with. Gradle auto-detects a local JDK 21
  (the JetBrains Runtime under `~/Library/Java` qualifies) — JAVA_HOME stays 17 for
  the daemon. Do NOT "simplify" the toolchain back to 17.
- iOS: **Xcode 26**, deployment target **iOS 17**. The Xcode project is **generated by
  XcodeGen** from `iosApp/project.yml` (edit the yml, not the `.xcodeproj`).

## Commands
```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home

# Run the shared-core unit tests (fast, no simulator)
./gradlew :shared:jvmTest

# Link the iOS simulator framework
./gradlew :shared:linkDebugFrameworkIosSimulatorArm64

# Regenerate the Xcode project after editing iosApp/project.yml
cd iosApp && xcodegen generate

# Build the iOS app (the Xcode build's pre-build script builds the KMP framework;
# JAVA_HOME is hard-coded in project.yml so Xcode GUI builds work too)
xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' build

# Run the iOS unit tests (needs a simulator; covers what jvmTest cannot —
# the Keychain KeyVault actual and the Swift↔Kotlin bridge)
xcodebuild test -project iosApp/iosApp.xcodeproj -scheme iosApp \
  -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17 Pro'

# Regenerate the app icon / launch mark after changing tools/Render*.swift
swift tools/RenderIcon.swift iosApp/iosApp/Assets.xcassets/AppIcon.appiconset/icon-1024.png day

# Android: unit tests, lint, and install on a running emulator/device
./gradlew :androidApp:testDebugUnitTest
./gradlew :androidApp:lintDebug       # catches minSdk-26 API misuse — do not skip
./gradlew :androidApp:installDebug

# Android release. Needs androidApp/keystore.properties (untracked) or the output is
# UNSIGNED on purpose — a release must never fall back to the debug key in a public repo.
./gradlew :androidApp:bundleRelease   # the .aab you upload to Play
./gradlew :androidApp:assembleRelease # an APK, for sideloading/testing only
```

**Play signing**: you sign the bundle ONCE with your own upload key; Google's Play App Signing
re-signs what reaches devices, automatically. Losing the upload key is recoverable (Google can
reset it); a self-managed signing key is not.

⚠️ Adding a file under `iosApp/` requires `xcodegen generate` before it is compiled —
a new test file silently does not run otherwise.

## iOS ↔ shared interop notes
- Kotlin `object X` → Swift `X.shared`. Kotlin `Int` → Swift `Int32`.
- Kotlin default arguments do **not** cross to Swift — pass all args.
- To avoid exposing `kotlinx-datetime` types to Swift, add String/Int-returning
  wrappers in `CyclunaCore.kt` (e.g. dates passed as ISO `yyyy-MM-dd` strings).

## Compliance & security
Cycluna is a **reproductive-health app** → App Store Guideline 5.1.3 + heightened
privacy law. Design for it from day one. Living checklist: **`COMPLIANCE.md`**.
Already in place: no-secrets-in-client, Keychain `KeyVault`, privacy manifest,
encryption declaration. Must design into the backend API: **account deletion**,
**data export**, **Sign in with Apple** (mandatory if Google is offered).

## Design fidelity + platform standards (guiding principle)
Match the **web app's visual identity + content**, keep **iOS ≈ Android**, but
implement with each platform's **standards** (HIG nav, native controls, accessibility,
Dynamic Type). Shared *logic* → KMP core (identical on both). Shared *design* → token/
spec system rendered natively (NOT a pixel-copy of the web DOM). The web app in
`../cycluna-moon-flow` is the visual reference (see `MoonWheel.tsx`, `PhaseCard.tsx`,
`Home.tsx`, `index.css` tokens).

## Product rules that are load-bearing
These were decided deliberately and are easy to undo by accident:

- **Never claim a pattern the data can't support.** Every insight sits behind guardrails
  (minimum logs, minimum per bucket, minimum gap) and returns `null` otherwise; the UI
  then shows an honest empty or "keep logging" state. "Your mood looks steady" is itself
  a claim about spread — it waits for `hasEnoughForClaim`, not merely for some data.
- **Never state a claim from a span the chart isn't showing.** Each Mood-patterns page
  names its own timeframe and draws conclusions only from that page.
- **No causal language about the moon.** The moon lens describes the user's own logs and
  carries a standing disclaimer. Research has not established a moon–mood link.
- **An overdue cycle stays open** (`CycleTracking.LATE` → `UNCLEAR` after
  `UNCLEAR_AFTER_LATE_DAYS`). Predictions that depend on a cycle that never began —
  the fertile tile, the predicted-cycles list — are withheld rather than invented.
- **Light-only.** No theme switch: the cream/mauve palette is the brand, `RootView` pins
  `.preferredColorScheme(.light)`, and there are no adaptive colours left in `Theme`.
- **English-only by decision** — no String Catalog, and fixed date patterns are fine.

## Platform gotchas already paid for
- **Launch screen must be a storyboard.** The `UILaunchScreen` Info.plist dictionary's
  `UIImageName` renders *nothing* (verified on device), and launch storyboards cannot
  resolve asset-catalogue images — the mark ships as loose PNGs in `iosApp/LaunchAssets/`.
- **App icon** is generated by `tools/RenderIcon.swift`: 1024×1024, **no alpha**, square,
  no pre-rounded corners. iOS caches home-screen icons — a plain reinstall keeps the old
  one; uninstall first, and restart SpringBoard on the simulator.
- **Bundle id is `net.quietflare.cycluna`.** It was `app.cycluna.iosApp` (the XcodeGen
  *target name* leaking into the shipping id). Changing it makes iOS treat the build as a
  different app, so older installs never update and must be deleted by hand.
- **Legal/support pages live in `../quiet-flare`** (the QuietFlare site), not this repo:
  `quietflare.net/cycluna{,/privacy,/support}`. The in-app policy duplicates the hosted
  text on purpose — it must read offline, and it claims the app makes no network requests.

## Android specifics worth knowing
- **minSdk 26 / target-compile 36.** Lint checks every API call against 26 — it has already
  caught two real crashes-in-waiting. `:androidApp:lintDebug` is not optional. 36 is Play's
  requirement for uploads from 31 Aug 2026, and it is also AGP 8.10's maximum `compileSdk` —
  the next bump needs a newer Gradle wrapper first.
- **AGP 8.10.1 is the ceiling** for the Gradle 8.11.1 wrapper. Plugin versions live in the
  root `build.gradle.kts` so the Kotlin plugin loads once for the whole build.
- **Light-only is enforced in three places**: a fixed `lightColorScheme`, `forceDarkAllowed=false`
  in the theme, and `enableEdgeToEdge(SystemBarStyle.light(...))` in `MainActivity`. The last
  one matters — the no-argument `enableEdgeToEdge()` picks bar-icon colour from the *system*
  dark-mode setting and drew white status icons on the cream background.
- **Reminders use `AlarmManager.setWindow`**, not exact alarms: `SCHEDULE_EXACT_ALARM` is
  denied by default on 14+ and is meant for alarm-clock apps. Android has no repeating
  *notification*, so the daily check-in re-arms itself in `ReminderReceiver`, and `BootReceiver`
  rebuilds everything after a reboot.
- **Reschedule effects must not be keyed on the settings they read.** Adding a lifecycle
  observer replays `ON_START` immediately, so a `DisposableEffect(settings)` re-ran the
  foreground path on every settings change — which silently un-did "delete everything" by
  rescheduling from the pre-delete snapshot. Read through `rememberUpdatedState` instead.
- **No `material-icons-extended`**: the drop, heart, leaf and sun are drawn in `Glyphs.kt`.
